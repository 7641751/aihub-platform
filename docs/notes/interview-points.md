## 1. 90 秒电梯陈述

> 「做的是一个**大模型应用的统一接入与治理平台**，两个进程：`gateway`（WebFlux 数据面，8080）负责把 OpenAI 兼容请求**字节级透传**给上游并做鉴权/限流/配额/路由/故障转移；
> `admin`（Spring MVC 控制面，8081）是**唯一真相源**，管租户、API Key、渠道、路由、限流策略、配额、审计，并伺服一个零构建管理台。
> 网关**不连数据库**：它拿控制面下发的**配置快照**（三级读取两级缓存）和**AES-GCM 密文渠道密钥**（本地解密）。
> 计量走 MQ 异步落 `request_log`，配额用 Redis+Lua 原子预扣、拿到真实 usage 再校正，每天凌晨按 `request_log` 重算账单并**只报告不自动改账**。
> 四个我认为最值得深挖的点：**SSE 直通与断连计量**、**限流的原子性与降级**、**两级缓存的一致性**、**异步流水线的全成或全清**。」

规模（`git rev-list --count HEAD` / `git ls-files`，2026-10-07 实测）：**244 个提交、357 个被跟踪文件、186 个 main 类 + 127 个测试类、3 条 Flyway 迁移**。

## 2. 六个深挖点（设计文档 §11 指定的六个，每个应能撑 5–8 分钟）

### 2.1 SSE 流式转发：背压、断连、半途失败的计量

**答案骨架**
- 转发是**字节级直通**：`exchangeToMono` + `writeAndFlushWith` 复制 `DataBuffer`，上游状态码 / `Content-Type` / 响应体字节**原样回写**；网关**不分流**（流式/非流式由请求体的 `stream` 字段决定）。
- 曾经有个 `SseAcceptNormalizingFilter`（改 `Accept` 头），后来**删掉了**——因为字节级透传不再需要它。
- 计量是**旁路观察者**：挂一只只读探针把经过的字节复制进**有界尾窗**，非流式从整体 JSON 读 `usage`，流式从最后一帧读；唯一被允许的请求体改写是注入 `stream_options.include_usage`。
- 断连：客户端中断在 `doFinally` 里以 `CANCEL` 信号捕获，事件按 `client_disconnected` 记。

**数字**：TTFT avg **127.4 ms** vs 整条流 avg **477.7 ms** ⇒ 若缓冲，TTFT 会≈总耗时。这是"流式转发"的**机器证据**，不是感觉。
真上游抽测（DashScope `qwen-turbo`）：TTFT avg **243 ms**、p95 301 ms，**同样未被缓冲**。（`design.md` §12 / `.superpowers/sdd/m6-load-report.md`）

**追问链**：背压怎么处理？→ 用 `writeAndFlushWith` 让 Reactor 按订阅者请求量拉取，天然背压。
半途断了 token 怎么算？→ 记 `usage_missing` / `prompt_tokens=0` 表示"未知"，**不假装是 0**；这一档必须当近似值，对账时会进偏差计数。

**踩过的坑（能显示真做过）**
- **一个异步副作用观测错了三次**：`subscribeOn(...).subscribe()` 是发后不管，"它跑完了没有"与 `block()` 返回**没有先后关系**；热态下约 2/3 轮次读到 `null`。修法是**有界等待 + 等不到就带着原因变红**，而不是加 sleep 或放宽断言（`CONVENTIONS` §8）。
- **`@Nested` 的外层类会打印 `Tests run: 0`**：按 `*.txt` 首行相加会少数（实测 349 vs 真实 355）⇒ 判据一律用**模块汇总行**或 `TEST-*.xml`。

### 2.2 限流：Lua 令牌桶的原子性、时钟漂移、Redis 挂掉怎么办

**答案骨架**
- **Redis + Lua 令牌桶**，判定与扣减在**一段脚本里原子完成**；策略按 **`tenant + api_key` 两个维度**选取（key 级覆盖 → 租户级回落 → 内置默认 `qps=10/burst=20`）；桶键 `aihub:ratelimit:{tenantId}:{sha256(secret)}` —— **不进 Redis 明文密钥**。
- **不用 Redis 的 `TIME`**：时钟基准来自应用侧传入的时间戳参数（决策 9），避免多实例时钟漂移造成桶状态被"穿越"。
- **降级 ≠ 放行**：Redis 挂了退化为**本机**令牌桶，超限照样 429；多实例下实际放行量约为「策略 × 实例数」（已登记为近似）。
- 预热/击穿：`RateLimitColdStartTest` / `RateLimitColdCacheAuthDisabledTest` 覆盖冷启动。

**数字**：限流开/关对照（同负载只切策略）—— 关 ⇒ `rate_limited=0`；开（`qps=50/burst=100`）⇒ **拒绝 759,036、通过 53.3/s**（与配置吻合）。429 形状是 OpenAI 形状 + `Retry-After`/`RateLimit-Limit`/`RateLimit-Remaining`，**刻意没有 `RateLimit-Reset`**（网关不写这个头）。

**追问链**：为什么不用现成限流库？→ 需要"租户+Key 两维策略 + 跨实例一致 + 降级仍拒绝"，且要能在 Lua 里一次原子完成；引库反而要绕过它的模型。
怎么防超卖？→ 脚本内 `HMGET`→计算→`HSET` 不可被打断。

**踩过的坑**：**简报给的测试体本身是假绿**——Mockito 展开 varargs 使 `getArgument(2)` 抛的 `ClassCastException` 被吞掉，得到一个"绿"的用例；改成切 `getArguments()` 并钉住 6 参约定才真的能证伪。

### 2.3 两级缓存：一致性、失效消息丢失、缓存击穿

**答案骨架**
- 三级读取两级缓存：**本机 Caffeine（30 s）→ 共享 Redis（10 min）→ 回源 admin**；singleflight 合并并发回源；版本比对决定是否采用。
- **主动失效**：控制面写完**提交之后**广播 `aihub:config:invalidate`（版本号 + reason），网关收到后同时**清本地 + 删共享条目 + 把写入水位抬到消息里的版本**（只抬不降）。
- **版本单调性**：水位持久化在 `config_version` 单行表（`GREATEST(version, ?)` upsert），修掉"删掉最新一行 ⇒ 版本倒退"的缺口。
- **失效消息丢了怎么办**：靠 TTL + 版本比对兜底 ⇒ 收敛上界回到共享条目 TTL（**≤10 分钟**），这是写着明账的降级。

**数字**：M3 实测**改配置 101 秒不可见**、手动删共享条目后 15 秒收敛；M4 接通广播后**秒级**。
控制器 2026-10-02 亲手测的"结论 + 反证"一对：订阅**开** ⇒ 新路由 **179.7 ms** 可见；置 `AIHUB_CONFIG_INVALIDATE_SUBSCRIPTION=false` 重建网关 ⇒ **120 秒窗口内始终不可见**，且该窗口内网关日志**共 15 行、失效订阅相关命中 0**；恢复订阅 ⇒ **202.5 ms** 可见。
缓存冷/热对照（20 把全新 key、探针 `GET /v1/models` 不经上游）：冷轮 p50 **14.0 ms** / max 268.5 ms 且冷轮结束 `aihub:apikey:*` **正好 20**（"真回源了"的机器证据）；热轮 p50 **5.3 ms** / max 6.9 ms ⇒ **p99 差 38.9×**，热轮那 ~5 ms 与压测反推的"网关自身开销 ≈ 5 ms"**互相印证**。

**追问链**：为什么不用 Redis 的 `keyspace notification`？→ 不可靠（丢事件、无版本语义）；用**显式版本 + 广播**才有"谁更新谁负责"的因果。
`invalidate` 为什么**不能重置**本地水位？→ 重置会让一个迟到的旧快照把新配置覆盖回去。

**踩过的坑**：**水位比较写成了 `<=`**，导致"同版本的重新填充"被拒 → 共享条目长期为空、每个实例每轮 TTL 都回源 admin（静默的**控制面锤击**）；改成严格 `<`，并让 `readRedis` 也把观察到的版本喂进水位的 `max`。

### 2.4 渠道故障转移：健康探测、权重选择、已输出内容怎么办

**答案骨架**
- 路由按 `model_route.priority` **分组**（数字小的组先服务），组内按 `weight` **加权随机**；`status != ACTIVE` 或不可用的渠道被排除；**熔断中的渠道排到最后而不是删除**。
- **故障转移只有两条规则**：上游结果**可切换**（仅 **429 与 5xx**；4xx 原样透传不换）**且响应尚未提交**（`response.isCommitted()` 为假）。一次请求最多 **3 条候选**。
- 上游 **429 额外给该渠道打一个 30 秒跨实例熔断标记**（Redis key，Redis 不可用退化为本机表）；5xx/超时不打熔断，只当次切换。
- 凭据**逐请求注入**、绝不挂到共享客户端上（`ChannelClientIsolationTest` 钉住）。

**数字 / 证据**：WireMock 注入 429/超时 ⇒ 自动切换（`WireMockChannelFaultInjectionTest` 8 例）；**"一旦有字节写回客户端就绝不再换"** 就是"仅在未输出任何 token 时允许切换"的机器形式。

**追问链**：为什么"已提交就不换"？→ 换个上游会把两段不同模型的输出拼在一起，且客户端的 `usage`/计费无法归属；宁可失败得诚实。
加权随机的权重怎么保证真的生效？→ 把随机源**构造器注入**（生产用 `RandomGenerator.getDefault()`，测试可播种），并用变异体证明"中和权重/永远取第一个"都会打红。

### 2.5 异步流水线：全成或全清、MQ 幂等、死信

**答案骨架**（M5）
- 两段 MQ 串联：`kb.parse` → `kb.embed`；**状态与进度都落 MySQL**（`kb_document` 状态 + `kb_chunk` 逐段进度），**Chroma 是可重建的派生数据，原件才是唯一真相源**。
- `READY` 的判据是「本 doc 的**所有** `kb_chunk` 行 `embedded_at` 非空」，**不是** `chunk_count`（那是期望值）。
- 重试耗尽 ⇒ **自定义 `MessageRecoverer`**：① 清 Chroma → ② 删 `kb_chunk` → ③ 置 `FAILED` + 审计 → 然后**必须抛 `AmqpRejectAndDontRequeueException`** 才进 `aihub.kb.dlq`。
- 幂等：`uk_kb_chunk_doc_seq(doc_id, seq)` + Chroma `upsert` ⇒ 至少一次语义，重放收敛。

**数字**：上传 **813,280 字节**的真 PDF ⇒ 日志 `解析完成：切出 9 段` ⇒ 无可用上游 ⇒ 终态 `FAILED(stage=embed)`，且 `kb_chunk` 0 行、Chroma count 0、原件保留 1 份、DLQ 1 条、审计两条。
"**中断上传不留脏数据**"（本里程碑的验收标准）在真实 compose 上复现：真发 539 字节却声明 5 MB 后断开 ⇒ `EOFException`，**行数仍为 1、盘上仍只 1 个文件**。
接真上游（`qwen3.7-text-embedding`，1024 维）验证到 `READY`（B 档）。

**追问链**：为什么"全清"要有反证？→ 若 cleanup 是空操作，`kb_chunk` 会停在 4 行/9 行；我们**实测终态为 0**，观测点因此有判别力。
为什么 recoverer 必须抛？→ Spring AMQP 里 `recover()` **正常返回等于容器 ack**（消息消失）；`catch → return` 会让"置 FAILED"与"进 DLQ"**只剩一半**。
跨语言契约怎么保证？→ 检索侧是**另一个仓库的 Python**，所以 collection 名 / `vector_id` 形状 / metadata 字段名都**写死在 `CONVENTIONS §6.8`**，改它就是破坏性变更。

**踩过的坑**：**"流水线终点后移"会让所有"等中间态"的断言变成竞态或假红**（等 `EMBEDDING` 在 embed 消费者落地后不再停靠）⇒ 判据一律盯**终态**或**不变量**。

### 2.6 计量与对账：usage 从哪来、重复消费、账单差异

**答案骨架**
- 网关在请求开始铸一个 UUID 写进响应头 `x-request-id`，`POST /v1/chat/completions` 同时把它当作计量事件的 `request_id`；**幂等键是 `(request_id, created_at)`，两个值都由网关生成**（消费端若用自己的 `now()`，每次重投都会写成新行）。
- 事件经 RabbitMQ 用**共享的分隔符文本 codec**（不是 JSON —— `aihub-common` 必须零依赖）；**只有 admin 声明拓扑**，网关只发布。
- broker 不可用：先在内存队列（有界）、再落磁盘 spool，定时重投；**任何丢弃都让 `dropped` 计数 +1 并打 ERROR**（绝不静默丢）。
- `request_log` 按**月分区**，由运行时维护（启动补齐 + 每日 03:10 前推 2 个月）；补建必须 `REORGANIZE PARTITION pmax`（有 `pmax` 时 `ADD PARTITION` 报 **ERROR 1493**）。
- 对账：每日 02:00 按 `request_log` 重算 `billing_daily` 并与 Redis 计数比对，**只报告与告警、不自动改账**。

**数字**：**RabbitMQ 挂 = 业务无感 + 计量零丢失**（恢复后**精确回补 370 条**）；k6 与 `request_log` 两个独立来源互证（流式 TTFT 行数 2,520 = `COUNT(ttft_ms)` 2,520）。

**追问链**：为什么不用事务消息 / 本地消息表？→ 这里是"**允许重复、必须不丢**"的场景，幂等键 + 至少一次比分布式事务便宜得多，且 DLQ 可观测。
账单为什么会差？→ 记的是**近似值**（`usage_missing`、`client_disconnected`、1 MiB 尾窗截断）⇒ 偏差天然存在，所以设计上**只报告**。

## 3. 跨领域加分点（很多候选人没有）

1. **假绿主动排查**：顺序条件绿（换 `-Dsurefire.runOrder=reversealphabetical` 就红）、`-Dtest=A+B` 静默只选一个、`failIfNoSpecifiedTests=false` 导致"**0 测试 BUILD SUCCESS**"——三类都被我实测复现过并写成纪律。**任何"绿"都必须能通过反序命令。**
2. **变异测试 + 还原证明**：每个新断言都要能回答"**哪个最小变异能让它红**"；还原**不能**用 `git diff` 证明（`target/classes` 会留变异体字节码，`Copy-Item` 还会保留 mtime 让 Maven 打印 `Nothing to compile`），必须 **SHA256 对比 + `MUTANT` 标记扫描 + `javap` 看真实字节**。
3. **三类"静默失败"**（我给它们起过名，面试很好展开）：
   - **`eq(column, null)` 恒不成立**：MyBatis-Plus 生成 `col = ?` 带 null ⇒ 恒 UNKNOWN ⇒ **静默返回 0 行**（实测 `eq(null)` 0 行、`isNull()` 1 行、裸 SQL 1 行）⇒ 可选维度必须 `isNull()`。
   - **`jacoco:prepare-agent` 在本仓库是静默空转**：`.mvn/maven.config` 的 `-DargLine=` 是**命令行用户属性**，优先级高于插件设置的项目属性 ⇒ surefire fork 的 JVM 不含 agent，`report` 打 `Skipping JaCoCo execution due to missing execution data file`，而 `mvn` **照样 BUILD SUCCESS**。判据不是退出码，是 `jacoco.exec` 非空。
   - **`catch → return` 让 DLQ 只剩一半**（见 2.5）。
4. **"每个数字必须点名产生它的命令或产物"**：连续三轮"修上一轮写错的话时又写错一句"，根因都是**数字从上一份报告里抄**。这条纪律现在已经写进 `CONVENTIONS §8`，可用于展示**文档工程能力**。
5. **覆盖率是量出来的，不是声称的**：JaCoCo 0.8.14、全部 777 条用例、`includes=com.aihub.*` ⇒ **六条核心链路行覆盖 91.07%**（鉴权 89.22 / 限流 96.84 / 配额 89.97 / 路由 98.26 / 计量 92.80 / 流水线 86.04），全仓 **92.48%**（227 类 / 5038 行）。复现命令写在 `README.md`「测试」。
6. **"基准"类问题（时间/版本/分页）**：`datetime(3)` 一律映射 `LocalDateTime` + 显式按 UTC 写；**符号感知**（非 UTC 连接写进去的行，位移量 = 该连接偏移，方向由符号决定 —— 东半球 fail-open、西半球提前过期）；版本回退缺口的成因与缓解。
7. **供应商/环境不变量要显式钉**：网关测试**必须跑在 Netty 上**（测试 classpath 一旦出现 servlet 容器会静默改跑 Jetty）；MySQL 分区补建用 `REORGANIZE` 而非 `ADD PARTITION`；JDK `HttpClient` 调明文 HTTP/1.1 上游必须 `.version(HTTP_1_1)`（否则发 h2c 前奏，uvicorn 报 422/400 —— 这个症状会把人往"请求体写错了"上带）。

## 4. 架构取舍（能画白板的那种）

| 取舍 | 结论 | 一句话理由 |
|---|---|---|
| 网关要不要连 MySQL | **不连** | 数据面要能独立构建/测试/扩容；控制面下发快照 + 密文，真相源只有一个 |
| 共享类型放哪 | `aihub-common` **main 作用域零第三方依赖** | gateway 与 admin 共用同一份契约；零依赖才能被两边与"跨语言的线格式"同时引用 |
| 为什么不引 `spring-boot-starter-security` / JWT 库 | **不引** | 会引入全局过滤器链与自动配置，与既有鉴权形成两套；控制台令牌用 JDK `javax.crypto` 自研 HS256 足够 |
| 渠道密钥怎么下发 | **admin 只发 AES-GCM 密文，网关本地解密** | 明文不跨网络、不进日志；密文自描述版本 `v{n}:{base64}` 让轮换与回退安全 |
| 配额降级为什么"放行"而限流"仍拒绝" | **两种语义** | 配额是**记账**（Redis 挂必须放行，否则会误拒付费用户）；限流是**保护**（降级仍要挡住超限） |
| 控制台要不要租户隔离 | **不要，但必须有升级门槛** | 它是**平台运营台**（"租户自助注册/细粒度 RBAC"是明确的非目标）；规则 R1–R4 与"出现第一个非平台方账号就必须先落地隔离"写在 `CONVENTIONS §10` |
| 为什么不用 MyBatis-Plus 的 `TenantLineInnerInterceptor` | **否决** | 控制面**不是**唯一数据访问方：网关经内部 HTTP 解析 key（无租户上下文）、MQ 消费者线程、`@Scheduled` 对账**必须跨租户** ⇒ 收益远小于风险，要做就在控制器/服务层显式带 `tenantId` |
| 管理台 | **零构建静态页**（vanilla JS + `fetch`，无 npm/无打包） | 把时间留给后端；代价是令牌放 `sessionStorage` 的 XSS 面（**已登记**） |

## 5. 「你踩过的最大的坑」——三个最好的故事

1. **Redis 降级每请求 ~10 秒**：现象是吞吐"塌 100 倍"，我一开始把它当"服务不可用"。查正的根因是**每请求 5–6 个串行的阻塞式 Redis 命令、各付满一次 2 s 超时**（日志原文 `Command timed out after 2 second(s)`；`5×2=10.157 s`、`6×2=12.160 s`，**不是**单次连接超时）；把网关 `spring.data.redis.timeout` **2 s → 300 ms** 后复验 **1.65 s**，再按"主动失效通道是否接上"给逐请求版本探测分档 ⇒ **0.44–0.75 s**，相对最初 **~20×**。并且实测 6 并发**无额外放大** ⇒ "塌 100 倍"其实应读作"**每请求变慢**"。两处修复都有守卫（`RedisTimeoutBudgetTest` 直读出厂 yml，>1 s 即红；`RedisVersionProbeTest` **双向**钉）。
2. **把测试夹具的方言现象当成生产缺陷并推上远端**：我曾把"时间列差 8 小时"写成生产缺陷（还写进了计划与约定并推送）。复核发现**发布的两个 JDBC URL 都钉了 `serverTimezone=UTC`**，旧代码在那种连接上**逐位相等**（`old − new = 0`）；8 小时只在"连接时区解析成 LOCAL"（测试裸 URL）时出现。⇒ 教训写成了纪律：**写进规范的每个隐患，都要在实际发布的配置上验证触发条件**；而且**结论要符号感知**，不是常量。
3. **一次被自己的探针骗了**：探测 Chroma 契约时我一度判定"文本进了向量库 ⇒ 契约被违反"——实际是我检查了 `documents` **数组是否非空**，而不是**元素是否为 null**（我主动 `include` 了该字段，服务端自然回一个等长数组）。改正后元素全为 `null`，契约成立。⇒ 与"不可证伪的断言"是同一类：**断言要能回答"哪个最小变异能让它红"，并说清它证伪不了什么。**

## 7. 已知边界（主动说出来，比被问出来好）

1. **真上游只有"抽测"量级**：2 VU × 20 s、单一上游单一模型、**未覆盖上游错误路径** ⇒ 不可当容量规划依据；与桩数据**口径不同不可混列**。
2. **控制台不隔离租户**（`ADMIN` 跨租户，`CONVENTIONS §10` 的 R1–R4）：这是**有意的设计**，但**升级门槛是硬的** —— 一旦出现非平台方账号 / 对非可信网络暴露 / 引入租户自助，**必须先落地隔离再继续开发**。
3. **控制台登录没有限流/锁定**（计划自己把它标为"最大的安全残余"，属 M4 边界）。
4. **未鉴权的 `/v1/**` 不会被限流**（鉴权在限流之前 401 掉）；**404/405 仍是 Spring 默认错误体**（非 OpenAI 形状）；**流中途上游断流不发 SSE `error` 事件**。
5. **`restart: unless-stopped` 不覆盖"Docker Desktop 自己退出"**（实测停了 21 小时、6 个容器全 `Exited`、一个都没自动回来；`compose up -d --no-build` 一命令恢复）——**只登记现象、未查根因**。
6. **`api_key.last_used_at` 没有写入方**（恒 NULL）、`chroma` 没有健康检查（用 `service_started`）、**语义缓存/提示词版本化/成本告警**都在"后续迭代不做"清单里。

**若问"接下来做什么"**：① 覆盖率门禁化（现在只测一次、没进构建）；② 把 README 的边界变成 issue/计划条目并排期（租户隔离、登录限流）；③ 与既有 Python RAG 仓库的**集成**（读侧契约我已实测：`kb_chunks` 的查/过滤/无文本/1024 维全部成立，但 Python 侧今天连的是**本地 `data/chroma_db` + `langchain_docs`**，两者**不是同一台库**）；④ 跨语言链路追踪（OpenTelemetry）。

## 8. 不要说的话（容易被戳穿）

- ❌ "全链路端到端验证过真实模型" ⇒ 真上游只是**抽测**；桩数据说明的是**网关自身开销**。
- ❌ "覆盖率大概 90% 左右" ⇒ 要么给出**命令与口径**（91.07% / 91.07% 是六条核心链路的行覆盖），要么别报数字。
- ❌ "我们做到了租户隔离" ⇒ 控制台**不隔离**，那是**有意的平台运营台**语义，且有升级门槛。
- ❌ "Redis 挂了我们照样 900 QPS" ⇒ 降级是**不误拒**，但**每请求变慢**（0.44–0.75 s），吞吐比≈延迟比。
- ❌ "缓存永不过期/永远一致" ⇒ 有 **30 s 本地 TTL + 10 min 共享 TTL**，失效消息丢失时收敛上界就是后者。
