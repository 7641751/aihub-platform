# M6 技术笔记：压测与打磨（部署硬化 / 故障注入）

> 素材：计划 `docs/superpowers/plans/2026-10-05-m6-load-and-hardening.md`；原始数据 `.superpowers/sdd/m6-load-report.md`
> 与 `.m6t2-logs/`。tag：**`m6`** → `f674e4d`。

## 目标

设计 §1.4/§10/§12 对 M6 的要求：**产出 QPS / P99 / TTFT，并给出「限流开/关」「缓存开/关」的对照数据**；
故障注入覆盖 Redis 挂 / MQ 挂 / **流中途断开**；落地"部署上线"。**非目标**：K8s（§2）、Prometheus/Grafana（§10 里是可选加分项）。

## 做了什么

1. **压测桩**（T1）：`load/stub/ChatStub.java` —— **JDK 单文件**程序（零构建、零新依赖、全 ASCII），
   参数化（首字延迟 / 每 token 延迟 / token 数 / **可注入中途断流**），配套 5 条契约测试（**先红后绿**）。
2. **基线**（T2）：桩作为主力上游 ⇒ 数据可重复、可归因到**我们自己的网关**；真上游只做抽测（本期未做，见边界）。
3. **对照实验**（T3/T4）：**限流开/关**（同一脚本、同负载，只切 DB 策略）；**缓存冷/热**（重启网关 + `FLUSHALL` 造冷）。
4. **故障注入**（T5）：Redis 停 / RabbitMQ 停 / 流中断（桩侧 + 客户端各一次），每条都走**注入 → 观测 → 恢复 → 复测基线**。
5. **部署硬化**（T6）：`restart: unless-stopped`、健康检查（探针工具**事前核实过**）、资源限制、必填变量校验。

## 实测数字（全部可复现，原始日志在 `.m6t2-logs/`）

| 轮 | QPS | P95 | P99 | TTFT | 失败率 |
|---|---|---|---|---|---|
| 非流式 50 VU×60s | **397.5 /s** | **129.6 ms** | **133.3 ms** | 125.3 ms | **0%** |
| 流式 20 VU×60s | **41.8 /s** | **490.9 ms** | **504.5 ms** | **127.4 ms** | **0%** |

- **网关自身开销 ≈ 5 ms**（桩配 120ms 首字）⇒ 这正是"用桩做主力上游"的意义。
- **流式未被缓冲**：TTFT 127ms ≪ 整条流 478ms（若缓冲了，TTFT 会≈478ms）—— 这是设计 §8.1"流式转发"的机器证据。
- **限流开/关**：关 ⇒ `rate_limited=0`；开（`qps=50/burst=100`）⇒ 拒绝 **759,036**、**通过 3,196/60s ≈ 53.3/s 与配置吻合**；
  被拒请求 avg **3.79 ms**（未触上游 ⇒ 保护了上游）。⚠️ **QPS 飙到 12,680 是"快速失败"，不是性能变好**。
- **缓存冷/热**：P99 **133 → 360 ms**，min 128.7 ≈ 热态均值（只有最初少数请求付回源成本）。
- **故障注入**：**MQ 挂 = 业务无感 + 计量零丢失**（`request_log` 55,022→55,392，**精确 +370**，`SpoolReplayer: 已重投 370 条`）；
  **Redis 挂 = 不误拒（无 401）但吞吐塌 ~100 倍**（0.34/s vs 35.6/s）；**流中断**两种变体均可检出（2 块 / 16 块，**均无 `[DONE]`**）
  且**两个被中断的请求都被计量**。
- **对账**：`request_log` 的 `COUNT(ttft_ms)=2,520` **精确等于** k6 流式轮请求数；TTFT 均值 123 vs 127（服务端偏低，可解释）。

## 踩坑与裁定

1. **上游选谁决定数据含义**：桩 ⇒ 归因到网关自身；真上游 ⇒ 主要测到上游与网络抖动。**两类数据必须分开列表**。
2. **"缓存开/关"用冷/热对照**（零代码改动）优于新加开关：YAGNI，且冷热差异本身就是缓存效果。
3. **探针要先探再写**：编一个镜像里不存在的健康检查探针 ⇒ `service_healthy` **永不满足**（M5 对 chroma 已经踩过）⇒
   这次先 `command -v curl` 核实（三个镜像都有 `/usr/bin/curl`），再写探针 ⇒ **一次就 `(healthy)`**。
4. **验收纪律**：故障注入只做"注入 + 观测"是**不够的** —— 必须**恢复并复测基线**，否则无法区分"契约成立"与"根本没测到"。
5. **工程卫生**：`Select-Object -First N` 会**终止上游管道**（把 `docker run` 杀掉，表现为"日志停在 22 秒、没有摘要"）；
   PowerShell 传 JSON 给原生命令会被**吃掉双引号**（网关日志给出铁证）⇒ 用 `--data-binary @file`。
6. **如实登记未做**：真上游抽测；**Redis 降级"每请求 ~10s"的根因未查**（只记现象 ⇒ 后续打磨首选）。
